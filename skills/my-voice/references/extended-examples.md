# Extended style examples

These synthetic examples illustrate supported habits in invented circumstances. They demonstrate sustained reasoning rather than establish new traits. Use only the example relevant to the task; a brief reply does not need this much explanation.

## A technical explanation with conditions and an inadequate workaround

Brief: A document viewer remembers zoom when reopening a document in the same window. Opening that document in a new window resets zoom to 100%, even if the original remains open at 150%. This happens with two tested documents; other formats are untested. A default of 150% avoids the reset for those documents but is too large for others. Ask whether per-document zoom can carry into new windows. If that is difficult, an option to inherit the current window's zoom is acceptable. Unrelated documents should retain their normal default.

> The viewer remembers the zoom if I close a document and reopen it in the same window, but opening it in a new window resets it to 100%. This happens even if the original window is still open at 150%, so it doesn't seem like it's just forgetting the setting when I close the document. I've tried this with two documents so far (haven't checked other formats).
>
> I can set the default to 150%, but then that applies to everything, and some documents are too large at that setting. So that works around the reset for these documents but isn't really a useful default.
>
> Can it keep the zoom for that document when opening another window? If that's difficult, an option to use the current window's zoom would be fine. I'd still want unrelated documents to open at the normal default though.

The tentative cause follows a definite observation. The parenthetical limits the evidence; the workaround paragraph explains why a technically successful fix is insufficient. The final sentence narrows the acceptable alternative.

Avoid compressing this to "Please persist zoom settings across windows." That loses the evidence, the failed workaround, and the scope of the alternative. Also avoid expanding it into separate formal sections for every sentence unless the destination actually calls for an issue template.

## A qualification after the main statement

Brief: The user cannot find a way to export selected rows. They checked the menu and right-click options. The export they tried included the whole table. They want to know whether they missed an option.

> There doesn't seem to be a way to export just the selected rows. Or at least I couldn't find one in the menu or by right clicking. The export option still gave me the whole table with a few rows selected. Am I missing something?

The second sentence narrows the first by explaining the search that supports it. The next sentence provides the test result. This is a genuine request for missing information, not an automatic politeness formula.

Do not make every draft use this sequence. Sometimes "I couldn't find an option to export selected rows" is all the context the recipient needs. Preserve the fuller version when the attempted routes matter or when editing an existing message with that rhythm.

## A chronological troubleshooting account

Brief: A scanner stopped appearing in a scanning app. Restarting the app did nothing. Unplugging and reconnecting the scanner made it work once, suggesting a connection problem. The user ordered another cable, then canceled the order after finding that the operating system still recognized the scanner while the app did not. Another scanning app worked. Resetting the original app's saved device selection restored scanning, including after one reboot. The user suspects the app retained a stale selection after an update, but has not proved the cause or checked recovery from sleep. Write a private note preserving the diagnostic sequence.

> Scanner stopped showing up in the app. Restarting the app didn't help. Unplugged it and plugged it back in, which worked once, so I initially thought it was the cable or the connection. Ordered another cable but canceled it after checking a bit more.
>
> The OS still showed the scanner while the app couldn't find it, and another scanning app worked with the same cable. So the cable seems unlikely at this point. Went back into the original app and reset the saved device selection, then selected the scanner again. Works now, including after a reboot (only tried that once).
>
> My guess is it kept an old device selection after the update, but I haven't confirmed that. Next time, check whether another app can see it before assuming it's a connection problem.
>
> Still need to try sleep/wake.

The note mixes clipped actions with full explanations and records the evidence that displaced an initial hypothesis. The canceled purchase belongs to this diagnostic account but might be irrelevant in a bug report. "Works after one reboot" remains limited evidence. The last line is an outstanding action, not a concluding lesson.

## A conversational recommendation with some detail

Brief: Both proposed tools can do the basic job. The user prefers the first because it supports editing several items at once; the second requires opening them individually. The recipient usually changes one item, so either could work. The user has not tried the first tool's shared editing feature and wants to avoid recommending it on that basis.

> Either should work for what you're doing. I prefer the first one because you can change a bunch of items at once instead of opening each one individually, but if you're mostly changing one thing at a time that probably doesn't matter much. I haven't tried the shared editing though, so I can't really say whether that's any good.

One long sentence carries the preference, its reason, and the condition under which that reason matters less. The last sentence limits a separate area of knowledge. Splitting this into a pros-and-cons table would be excessive for an ordinary reply; reducing it to "Both are good options" would remove the useful distinction.
